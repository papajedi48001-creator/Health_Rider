# UAT Checklist — Health Rider

วันที่ทดสอบ: __________  สภาพแวดล้อม: Staging / UAT  ผู้ประสานงาน: __________

สถานะต่อรายการ: ผ่าน / ไม่ผ่าน / รอทดสอบ
หลักฐาน: เลข ticket, ภาพหน้าจอที่ไม่เปิดเผยข้อมูลเกินจำเป็น, หรือไฟล์ log ที่ปกปิด secret แล้ว

## 1. ก่อนเริ่มทดสอบ

- [ ] มี URL ของ Health Rider staging และ MariaDB แยกจาก production
- [ ] `AUTH_SECRET` และรหัสผ่าน Compose ไม่ใช่ค่า development
- [ ] HOSxP account เป็น read-only และ `HOS_DATABASE_URL` เชื่อมเฉพาะ staging/ข้อมูลทดสอบ
- [ ] ตั้ง `HOS_ELIGIBLE_ITEM_CODES` ตามรายการยาที่อนุมัติสำหรับ UAT
- [ ] สร้างบัญชีทดสอบ: pharmacy, rider ภายใน, rider ผู้รับจ้างภายนอก, coordinator, admin, auditor
- [ ] เตรียมผู้ป่วย/ใบสั่งยาทดสอบที่ไม่มีข้อมูลจริง หรือได้รับอนุญาตตามนโยบายโรงพยาบาล
- [ ] สำรอง MariaDB และ evidence volume ก่อนเริ่มรอบ UAT

## 2. HOSxP และเภสัชกรรม

| รายการทดสอบ | ผลที่คาดหวัง | ผล/หลักฐาน |
| --- | --- | --- |
| HOSxP candidate | เห็นเฉพาะ candidate ที่เข้าเกณฑ์; ไม่มีข้อมูลยา/CID เกินความจำเป็น | |
| ยืนยัน candidate | เฉพาะ pharmacy/admin ยืนยันได้ และสร้าง Delivery Request หนึ่งรายการ | |
| โซน/หมู่บ้าน | ระบบเลือก zone/village เดิมเพื่อระบุพื้นที่ส่งยา | |
| เตรียมพัสดุ | สร้าง Delivery Attempt สถานะ `prepared` พร้อม QR | |
| QR | payload ไม่มี HN, ชื่อผู้ป่วย หรือข้อมูลยา; QR หมดอายุตามกำหนด | |

## 3. Rider และการส่งยา

| รายการทดสอบ | ผลที่คาดหวัง | ผล/หลักฐาน |
| --- | --- | --- |
| QR claim ออนไลน์ | rider ที่ล็อกอินสแกนแล้วรับงานได้เพียงคนเดียว | |
| QR claim ซ้ำ | rider คนที่สองได้รับ conflict โดยไม่เห็นข้อมูลผู้ป่วย | |
| ข้อมูลที่เห็น | rider ที่ claim เห็นชื่อ HN อายุ โทรศัพท์ ที่อยู่เท่านั้น; ไม่เห็นยา/CID/ประวัติ | |
| รับยา offline | ปิดเครือข่ายหลัง claim แล้วบันทึกรับยาได้ พร้อม device time และ UUID | |
| ส่งยา offline | เก็บเวลา ความสัมพันธ์ผู้รับ และหลักฐานแบบ privacy-preserving ไว้ในเครื่องเข้ารหัส | |
| Sync หลังออนไลน์ | event ส่งครั้งเดียวแบบ idempotent, มี server time และลบ local record หลัง acknowledge เท่านั้น | |
| ปิด/เปิดหน้าใหม่ | event ที่ยังไม่ sync กลับเข้าคิวได้; event ที่ acknowledge แล้วไม่กลับมา | |

## 4. ข้อยกเว้นและการประสานงาน

| รายการทดสอบ | ผลที่คาดหวัง | ผล/หลักฐาน |
| --- | --- | --- |
| ส่งไม่สำเร็จ | rider ต้องเลือกเหตุผลมาตรฐาน และสถานะเป็น `return_required` | |
| รับยาคืน | pharmacy ยืนยันได้เฉพาะงานที่รอคืน และภายในวันเดียวกัน | |
| Retry | ออก attempt/QR ใหม่ได้หลังรับยาคืนแล้วเท่านั้น | |
| แก้ข้อมูลระหว่างส่ง | coordinator/admin แก้ได้เฉพาะที่อยู่/โทรศัพท์ พร้อมเหตุผล, old/new audit และ delivery version ใหม่ | |
| HN/พัสดุ | ไม่สามารถแก้ HN หรือ identity ของพัสดุ | |
| Sync conflict | หลักฐานจาก version เก่ายังคงอยู่ใน queue ให้ coordinator ตรวจ; ไม่ถูกลบ | |

## 5. สิทธิ์และ Audit

| รายการทดสอบ | ผลที่คาดหวัง | ผล/หลักฐาน |
| --- | --- | --- |
| Audit | auditor อ่านประวัติได้ แต่ไม่มี route/action สำหรับแก้ไขหรือลบ | |
| บทบาท | ไม่มีบัญชีหรือหน้าจอสำหรับการคำนวณและจัดการค่าบริการ | |

## 6. เกณฑ์รับรอง UAT

- [ ] ไม่มี Critical/High defect ค้างอยู่ใน workflow ส่งยา, สิทธิ์ หรือ offline sync
- [ ] ทุกกรณีในตารางมีผลและหลักฐานแนบ
- [ ] ผู้แทน pharmacy, rider และ coordinator รับรองผลในส่วนของตน
- [ ] Backup/restore drill, HOSxP connectivity และ credential rotation ได้รับการรับรองแยกตามนโยบายโรงพยาบาล
- [ ] มีแผน rollback และผู้รับผิดชอบวันเปิดใช้งาน
